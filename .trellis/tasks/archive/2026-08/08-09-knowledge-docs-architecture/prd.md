# 知识中心文档架构重构

## Goal

把所有 `/knowledge/:key` 子路由统一重构为受 CC Switch 文档站启发的知识阅读系统：在桌面端形成“章节导航—主内容—页内目录”三栏结构，在移动端保留清晰、可操作、无横向溢出的阅读体验，同时继续使用 Praxis 现有的暖纸张色、衬线标题、细线分隔、双主题与静态 Markdown 内容模型。

这次改造的用户价值是：读者能知道自己位于哪个知识章节、能快速跳到其他章节或当前页面的小节，并在章节页与文章页之间获得一致的阅读心智。

## Background

- `apps/web/src/pages/knowledge/[key].astro` 是五个固定章节 slug 与全部公开非项目内容 slug 的唯一动态路由所有者。
- 五个知识章节及其稳定顺序由 `apps/web/src/lib/content/domain.ts` 的 `knowledgeSections` 注册表维护。
- 当前章节页使用 `PageHero` 加内容卡片，文章页使用通用 `ContentLayout`；两者没有共享的文档导航或页内目录。
- 当前公开知识内容只有两篇，且没有显式 `knowledgeSections` 归类；空章节必须继续如实呈现，不能为填充版式伪造文章。
- `/knowledge` 总览页、顶部知识下拉菜单、canonical URL、Sitemap、兼容路由与 Markdown 事实源已经形成稳定公开契约。
- 视觉参考已保存在 `research/ccswitch-docs-reference.png` 与 `research/praxis-knowledge-menu-reference.png`。

## Requirements

### R1. 覆盖范围

- 重构全部 `/knowledge/:key` 子页面，包括五个固定章节页和所有公开知识文章详情页。
- `/knowledge` 总览页不做结构性视觉重构；允许因共享注册表或导航能力获得一致性更新。
- 不改变既有路径、canonical、Sitemap、兼容跳转或公开内容选择规则。

### R2. 统一文档壳层

- 所有知识子页面使用同一套文档壳层。
- 桌面宽屏依次呈现左侧章节导航、中间主内容、右侧“本页内容”。
- 壳层必须延续 Praxis 现有设计令牌，不直接复制 CC Switch 的品牌、Logo、色板或圆角风格。

### R3. 左侧章节导航

- 显示知识总览入口、按稳定顺序排列的五个章节，以及可用的最近更新文章入口。
- 当前章节或当前文章必须有明确且可访问的状态。
- 提供站内知识筛选输入与 `Ctrl/⌘ + K` 聚焦捷径；筛选仅作用于当前页面已渲染的导航项目，不引入后端搜索。
- JavaScript 不可用时，全部真实链接仍然可见、可跟随。

### R4. 章节页内容架构

- 每个章节页显示章节编号、标题、描述与明确的“本章定位”。
- 每个章节拥有简洁的主题范围清单，用来解释信息架构，不冒充已发布文章。
- “本章内容”区域只渲染作者显式归类的真实内容；无内容时继续使用真实空状态。
- 提供相邻章节导航与返回知识总览的路径。

### R5. 文章页内容架构

- 文章详情继续显示真实标题、摘要、类型、阶段、状态、发布日期、更新日期、标签、正文、Journey 与 Practice Timeline。
- 文章正文的二级、三级标题生成右侧页内目录，并链接到 Markdown 渲染器生成的稳定锚点。
- 文章没有可用标题时，“本页内容”保持语义完整，不生成无效链接。
- 文章继续返回 `/knowledge`，不根据多选章节猜测唯一父级。

### R6. 响应式与阅读体验

- 宽屏三栏、中等宽度双栏或单栏、窄屏单栏必须形成明确降级。
- 在窄屏上章节导航与页内目录使用原生、可键盘操作的折叠结构；主要内容优先且页面不横向滚动。
- 桌面侧栏可粘滞，但不得遮挡顶部粘滞导航或造成视口内控件不可达。

### R7. 主题、可访问性与渐进增强

- Light 与 Dark 都使用语义令牌设计，保持足够对比度与可见焦点。
- 页面必须有一个 H1、正确的 landmark、真实链接、合理的键盘顺序与 reduced-motion 行为。
- 筛选和滚动位置高亮属于渐进增强；核心内容与导航不依赖 JavaScript。
- 新增浏览器脚本必须是 CSP 兼容的外部脚本。

### R8. 视觉质量

- 保留参考站的文档信息架构、密度、对齐逻辑和目录心智，同时使用 Praxis 的编辑型排版与视觉令牌。
- 最终实现必须以相同桌面视口对照参考截图，并完成 Light、Dark、移动端的浏览器目检。
- Product Design QA 必须记录源参考、实现截图、关键交互、比较历史和最终结果。

### R9. 第二轮细节精修

- 以用户最新提供的 CC Switch 收拢态文档截图为精修基准，重点学习其宽屏留白、三栏比例、首屏对齐、单行导航密度和目录层级，不复制品牌资产。
- 宽屏文档容器应更充分利用横向空间，左侧搜索、主标题和右侧目录形成清晰的首屏对齐关系。
- 左侧章节行应减少重复文案与伪图标感，保留真实计数、稳定编号、明确选中态和可用于筛选的描述数据。
- 桌面侧栏与目录应避免不必要的嵌套滚动条；移动端仍使用原生折叠并保持描述可读。
- 章节与文章首屏应减少无信息的大块留白，同时保留 Praxis 的衬线标题、暖纸张色、扁平细线和双主题。

## Acceptance Criteria

- [ ] AC1：五个固定章节 URL 与两篇现有公开文章 URL 均渲染统一知识文档壳层，且每页只有一个可见 H1。
- [ ] AC2：在 1536px 宽桌面视口，页面同时可见左侧章节导航、主内容和右侧页内目录，三栏不重叠且文档无横向溢出。
- [ ] AC3：左侧导航按注册表顺序显示五个章节；当前章节或当前文章拥有可见状态和正确的 `aria-current`。
- [ ] AC4：所有章节页显示章节编号、定位说明、主题范围、本章真实内容或真实空状态，以及可用的相邻章节/总览导航。
- [ ] AC5：文章页保留现有元数据、正文、Journey 和 Practice Timeline；二级/三级正文标题出现在页内目录并能通过锚点到达。
- [ ] AC6：知识筛选能按标签与描述过滤导航项目，`Ctrl/⌘ + K` 能聚焦输入，并向辅助技术公布结果状态。
- [ ] AC7：禁用 JavaScript 后，章节导航、文章正文、空状态、返回路径与页内锚点仍可读取和使用。
- [ ] AC8：在 320px 和项目移动端视口下，页面无文档级横向滚动，折叠导航可由键盘操作，粘滞侧栏不遮挡内容。
- [ ] AC9：Light 与 Dark 下目标页面通过 Axe 基础扫描，键盘焦点清晰，reduced-motion 下没有必要性动画。
- [ ] AC10：既有 `/knowledge` 总览、知识下拉菜单、canonical、Sitemap、兼容路由、内容 schema 与显式章节归类契约保持通过。
- [ ] AC11：`format:check`、`lint`、`typecheck`、`test:unit`、`build` 与相关 E2E 全部通过。
- [ ] AC12：项目根目录 `design-qa.md` 的本轮报告包含同视口可视比较，且 `final result` 为 `passed`。
- [ ] AC13：在 1920px 视口下，文档容器接近参考站的宽屏利用率，左栏、正文和目录的首屏视觉起点协调，且无内部双滚动条。
- [ ] AC14：章节导航桌面态为紧凑单行结构，真实计数不再显示为易误读的双字符；移动展开态仍能读取章节描述。

## Out of Scope

- 不重写 `/knowledge` 总览页的 Editorial Hero 与章节卡片布局。
- 不修改现有 Markdown 正文，不替作者补写文章，也不自动推断或批量写入 `knowledgeSections`。
- 不增加 CMS、数据库、服务端搜索、外部搜索服务或新的后端/API 边界。
- 不重构 `/projects`、`/journey`、`/about` 或项目详情使用的通用 `ContentLayout`。
- 不改变顶部主导航的信息架构或五个知识章节的名称、slug 与稳定顺序。

## Risks and Deferred Items

- 现有前端规范明确写着知识子页面继续使用 `PageHero`；本需求有意替换该旧约定，完成实现与验证后必须同步更新 `.trellis/spec/frontend/component-guidelines.md`。
- 当前两篇文章未归类到任何知识章节，因此五个章节仍会显示空状态；这是内容事实，不是视觉缺陷。
- 客户端筛选只覆盖已静态渲染的导航数据；真正的全文检索在未来内容规模需要时另立任务。
