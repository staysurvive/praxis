# Praxis v0.1 上线 Checklist

> 每个勾选项都必须有命令输出、浏览器检查或生产结果作为证据。正式域名和服务器接入完成前，生产部署与上线后检查保持未完成。

## 产品与内容

- [x] 首页清晰呈现“知行合一”与“知而思、思而行、行而成”，三个阶段不是导航栏目。
- [x] 首页 Now 与 Praxis 项目内容反映当前真实进度，没有把尚未部署写成已经上线。
- [x] 正式内容只有 `content/projects/praxis.mdx`，没有发布测试 fixture 或虚构文章。
- [x] 项目永久 `contentId` 和 `/projects/praxis-foundation` URL 保持不变。
- [x] Practice Heatmap 只统计 `publishedAt` 与显式 `practiceLog`，不依赖 GitHub 或外部 API。

## SEO 与发现性

- [x] 首页、列表页、详情页具有正确的 title、description 和 canonical URL。
- [x] 所有公开页面输出 Open Graph、Twitter card 与 RSS autodiscovery。
- [x] 项目详情输出 article 类型、发布时间、更新时间和标签元数据。
- [x] `/rss.xml` 只包含真实、非草稿内容和规范绝对 URL。
- [x] Sitemap 包含首页、四个类型列表和公开详情，不包含 404、RSS、robots 或生成 JSON。
- [x] `/robots.txt` 允许公开抓取并指向 Sitemap。
- [x] 404 返回 HTTP 404，输出 `noindex, nofollow`，且不进入 Sitemap。

## 质量与兼容性

- [x] `npm run check` 通过格式、lint、严格类型与单元测试。
- [x] `npm run build` 生成完整静态产物。
- [x] `npm run test:e2e` 在桌面 Chromium 与 Pixel 7 配置下全部通过。
- [x] 首页和项目详情在 Light/Dark 下通过 Axe 基础可访问性检查。
- [x] Light/Dark 主题、键盘焦点、移动端排版和 404 经过浏览器检查。
- [x] 关闭 JavaScript 后仍可导航并阅读项目正文。
- [x] reduced-motion 条件下没有依赖动画才能理解或操作的内容。

## 构建与部署产物

- [x] `apps/web/dist/` 包含首页、类型列表、项目详情、404、RSS、Sitemap、robots 与 Practice JSON。
- [x] Sitemap 和 RSS 使用测试构建指定的 `SITE_URL`，没有混入本地地址。
- [x] `docker build -f infra/Dockerfile.web -t praxis-web-v0.1-check .` 成功。
- [x] Docker 导出的静态产物可以由普通文件服务器读取，不依赖 FastAPI 或数据库。

## 生产部署

- [ ] 确认公开署名、简介和最终域名。
- [ ] 备份服务器现有 Docker Compose 与 Caddy 配置。
- [ ] 生产构建显式设置真实 `SITE_URL`。
- [ ] 将 `praxis-web-dist` 只读挂载到现有 Caddy，不增加第二代理层。
- [ ] 合并并审阅 Praxis Caddy site block，保留现有证书与网络配置。
- [ ] Caddy 配置校验通过并平滑 reload。

## 上线后检查

- [ ] 正式域名 HTTPS 证书有效，HTTP 正确跳转到 HTTPS。
- [ ] 首页、四个类型列表、项目详情和未知路径返回预期状态码。
- [ ] 正式域名下 canonical、RSS、Sitemap 和 robots 使用同一 origin。
- [ ] 桌面与移动端完成一次真实网络 smoke test。
- [ ] Light/Dark、无 JavaScript阅读和热力图在生产环境正常。
- [ ] 部署结果写回 Praxis `journey` 与 `practiceLog`，再将 v0.1 标记为已发布。
